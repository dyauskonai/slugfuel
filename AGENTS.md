# Repository guidance

Read `README.md`, `docs/product.md`, and the relevant folder README before changing this project.

## Current stage

This repository was created as a logistical foundation. No application code or dependency scaffold has been requested yet. Begin implementation when the user explicitly asks for it; do not treat documented future features as authorization to build them automatically.

## Working principles

- Keep changes focused on the requested milestone.
- Preserve the separation between interface, domain calculations, recommendations, and importing.
- Keep planned features distinct from implemented behavior in documentation.
- Never invent nutrition values, live menus, user counts, accuracy, or performance results.
- Preserve source provenance, serving units, menu dates, and unknown values.
- Keep credentials and private user data out of source control.
- Add meaningful checks for arithmetic, exclusions, data access, and import failures as those features are implemented.
- Update verified setup commands when tooling is introduced.
- Avoid adding libraries, services, or infrastructure without a concrete need.
- Explain design choices and implementation in a way the student owner can learn from and discuss in an interview.
